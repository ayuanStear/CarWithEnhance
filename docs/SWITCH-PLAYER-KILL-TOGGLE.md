# CarWithEnhance 切换播放器结束旧进程开关

## 结论

已新增菜单开关：

```text
切换播放器播放后结束上个进程
```

设置键：

```text
hook_switch_player_kill_previous_enabled
```

默认开启，兼容此前“切换播放器后结束旧播放器”的行为。

## 根因

- `HookConfigs` 只注册了 3 个菜单项，没有该功能开关。
- `AutoPlayAllHook#onMediaActuallyPlaying()` 会无条件尝试结束上一个播放器，不读取菜单设置。
- 之前的音轨保护逻辑在旧媒体 Session 未释放时会保留旧进程，因此用户看到的结果等同于“没有结束”。

## 实现

- 菜单新增独立 `HookItem`，手机端和车机端设置页会通过现有动态注入逻辑自动展示。
- 仅当以下条件同时满足时结束旧播放器：
  1. 菜单开关开启；
  2. 新播放器已经进入 `PlaybackState.STATE_PLAYING`；
  3. 旧包名与新包名不同；
  4. 旧播放器不是地图或保护应用。
- 开关关闭时保留旧进程，只记录切换并阻止旧播放器在本次连接内自动切回。
- 开关开启时先请求旧播放器释放音轨和 Session；若等待后 Session 仍未释放，仍按用户选择执行 `forceStopPackage`。

## 实车验证步骤

1. 在 CarWithEnhance 菜单打开“切换播放器播放后结束上个进程”。
2. 先用一个音乐播放器播放。
3. 在车机切到另一个播放器并开始播放。
4. 日志应出现：

```text
检测到 <新播放器> 真正开始播放，结束上一个播放器: <旧播放器>
已结束播放器: <旧播放器> (切换到 <新播放器>)
```

5. 关闭菜单开关后重复上述操作，旧播放器进程应保留，日志应出现：

```text
切换播放器结束旧进程开关关闭，保留上一个播放器: <旧播放器>
```
